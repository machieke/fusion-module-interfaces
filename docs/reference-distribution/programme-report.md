## State, recovery and authority

Each mutable service has a dedicated PVC, one StatefulSet ordinal, process lock and composition seal. Explicit ConfigMaps and per-service existing Secret references replace shared mutable policy files. HTTPS identities, scope/profile/recipient/occurrence/view bindings and current permission are checked at their selected boundaries. Credential rotation and a compatible chart rollback preserve existing state; incompatible composition refuses startup. Namespace ownership checks protect `omega-demo` and unrelated resources.

The restore drill quiesces each independent owner, checkpoints its WAL, hashes its files and extracts into fresh fenced PVCs. It is not a distributed atomic snapshot. Restored observers can read captured data and rebuild Search through its source ports; they cannot resend IRC output, reserve model work or submit a chain commitment. Old spent/unknown accounting is retained. A missing old Search view refuses instead of silently following a rebuilt latest view. Active approvals, TLS keys and signing authority are excluded from backup.

Diagnostics read only the selected pod's own stores. They expose bounded counts, spent/captured stages, publication heads, typed persisted failures and chain finality without content labels. Standard metrics do not claim a complete historical error/replay count where owners do not store one. Resource observations distinguish cold setup, application stage intervals, native E5 time, query/RPC latency and non-work-bearing health RTT. The first sample's unavailable cgroup-v2 counters remain unavailable; later sampling recognizes this host's actual v1 membership.
