# Synthetic private scopes and independent model selection

The fresh Phase 3 composition selects separate synthetic A and B scopes across
AtomStorage/feed, Chroma, E5 invocation journals, C1 source/history, C2 belief,
wall-clock Attention and Relations. Each existing service retains one writer and
its own PVC. Trusted configuration selects the scope partition; scope authority
is checked before constructing its owner. Search continues consuming declared
storage/feed ports. No consumer mounts a foreign journal.

A private session excludes delegation, inspection/chain publication and bounded
workspace tools from its selected catalogue. This is an explicit subset of the
existing twenty tools, not a new family count. Private native output is not
copied to ordinary worker logs; bounded method timings contain no arguments,
results or prompts. Scoped provider/workbench disclosure remains mandatory even
for captured results. This is synthetic single-host isolation, not a malicious
host or production multi-tenant confidentiality claim.

One operator-only `operator-approved-synthetic-projection/1` action can disclose
exact approved content from a private memory into a separately identified shared
artifact. It requires current operator authority in both scopes and binds an
approval record, source and exact content. Public identity is independently
allocated; the artifact excludes private IDs, hashes and provenance. Its label
explicitly denies independent empirical corroboration. A model command cannot
request or approve this action. Acceptance, private source capture, shared owner
publication and application receipt capture remain independent commits. Recovery
observes the original public write, with no repeated create after capture.

`omega-preview-model-binding/1` separates a recorded-response selection from the
existing pinned real Ollama adapter. The native consumer, parser, ModelAdoption
and full-batch authorization remain the same. Real selection calls the existing
campaign approval validator before provider acceptance and again before work
reservation. Missing, wrong or expired approval refuses before backend
construction, model assets or network contact. Accepted/captured work does not
receive a new allowance after reconnection. Selecting an endpoint or setting an
enabled flag is never approval.

Offline qualification uses recorded HTTP responses at the existing adapter's
SDK boundary and exercises its actual request/native-response translation. An
actual native consumer with real selection and missing approval is also tested:
no provider acceptance, reservation or backend call occurs. This does not claim
real generation. `REAL_PREVIEW_MODEL_EXECUTION=NOT_RUN` and
`ADDITIONAL_LIVE_GENERATIONS=0`. The protected campaign remains independent.

The approved projection is a bounded proper literal excerpt (at most 512 UTF-8
bytes) present in the generated source. Full raw source content is refused.
The operator supplies the exact excerpt; the service does not summarize or
infer a sanitized answer. The qualification selects `cabinet birch`, retaining
the private canary and source wrapper exclusively in the private scope.
