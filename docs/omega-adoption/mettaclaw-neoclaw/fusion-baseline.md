## Three different coverage measures

1. **Module responsibility coverage:** 9/15 families have source-observed Omega responsibility analogues: AtomStorage, Relations, Search, C1, C2, PLNKernel, Attention, Messaging, DelegatedExecution. This includes mixed or incomplete behavior. Six have no current counterpart: DA, C4, Registry, Resolver, ConsensusFinality, Authorization.
2. **Operation inventory coverage:** 19 advertised commands, runtime receive, model/embedding/vision helpers, persistent-space functions, NAL truth/rule clauses and imported runtime entries are traced. [Coverage JSON](coverage.json) counts semantic rows and source occurrences. Multiple clauses/overloads are counted separately, not as independent modules. Arbitrary dynamically imported user code is outside this finite source inventory.
3. **Behavioral contract coverage:** **0 Omega-to-Fusion conformance gates demonstrated.** The map proves neither independent module substitution nor remote recovery for Omega. Native isolated math and local/fixture probes support specific findings only. Fusion's historical behavior tests cannot be transferred to MeTTaClaw by naming a matching family.

Out-of-inventory model, embedding, perception, tool-schema and execution-policy gaps stay outside the denominator. Existing private/runtime state is neither inspected nor migrated. This boundary is essential to an honest coverage assessment.
