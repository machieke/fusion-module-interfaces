## Responsibility and contracts

Attention owns authoritative promotion values/times, retained revisions, bound work identities, clock high-water marks, numerical reservations and receipts. It receives opaque UUIDs and scope/context; it does not read memory content, Chroma, E5, evidence, STVs or cognitive databases. An independent atomic-file storage fixture implements the same policy without inheriting the SQLite owner's transitions or reading its tables. Both use the same closed DTO validation and pure native numerical dependency.

Application owns command occurrence, alias resolution, selected corpus/belief views and handoff. AtomStorage owns payloads and the replayable enrollment feed. Search owns the vector index. C1/C2 retain beliefs and provenance. Native tuple sorting, promoted prefix, candidate merging, uniqueness, limits and rendering remain native.

`bind` durably selects the owner's current revision and a trusted epoch sample before evaluation. `adjust` atomically commits value, time, new revision and exact receipt. `scores` returns every requested candidate, including zero. `rank` covers all eligible memories in the selected corpus view, independently of vector candidates, with positive filtering and native `(-score, UUID)` ties. `observe` recovers a committed result after expiry without new work. Current authorization applies to effects, reads, observations, cached release and hydration. See [executable contract decisions](s05-contract-decisions.md).

The numerical adapter extracts the original promotion expression and native cap/floor expressions, then executes them under pinned PeTTa/SWI. Production Python validates domains and receipts; it does not replace the policy arithmetic. Its runtime validator checks the existing binary/library pins, PeTTa interpreter sources and native memory source. A [reduced-source test](../../../evidence/s05/runtime-guards/minimal-native-source.json) executes both owners with MeTTaClaw NAL and PeTTa cognitive libraries absent, and rejects altered policy/interpreter source. This profile has no conserved STI budget, no belief weighting and no inference control.

Native feedback, global rendered segments and the derived file agree with the oracle. Distinct query ties (distance before UUID) and global ties (UUID after score) are compared separately.

The same controlled session can remember, assess, change priority and query. [Mixed-owner evidence](../../../evidence/s05/runtime-native-recheck/belief-independence.json) shows priority values `1 → 2 → 1` while support and contrary assessments remain C1/C2 events and decisions. Priority changes add no evidence weight, numerical belief revision, enrollment or index publication. The one memory-vector capture and one index maintenance operation in that sequence belong to `remember`; ordinary query encodings remain expected effects.

Global context runs before command creation. A bounded application context identity selects a corpus/belief view and Attention revision/time; ranking, ordered verified AtomStorage hydration and native rendering are captured before handoff. Source membership comes from the authoritative commit feed, not a Search query, foreign owner database or supplied answer list. A real separately scoped enrollment stays outside that view. Adapted startup forbids legacy promotion helpers and also succeeds with the generated legacy promotion file deleted.

The compatibility promoted-memory file is private derived output, written atomically from captured native lines. Deleting and reconstructing only that file preserves exact historical content and leaves Attention, belief and Search state unchanged. Missing payloads, malformed ranks and unavailable owners fail; none yields an empty/default priority fallback.

## Recovery and intentional restrictions

A retry recovers the same occurrence/time/receipt. Identical intentional commands in different positions each adjust once; two priority commands in a batch execute in order. Mixed-operation batches remain refused before effects. At saturation or floor, a new occurrence still commits time and a receipt.

Native promotion arguments contain spaces; their original wrappers do not replace underscores. Missing or ambiguous timestamp aliases now fail instead of silently succeeding or affecting multiple memories. Invalid/nonfinite numbers, conversion overflow and backward trusted samples fail explicitly. The high-water mark is per principal/scope/context, with zero tolerance and equal times allowed. Historical bound reads remain valid. SQLite legacy journals are inspected read-only and refused before WAL/schema changes; no migration or seal replacement occurs.

The native kill matrix exercises accepted command, bound clock, evaluated-but-uncommitted adjustment, owner commit, application visibility, native result capture, global selection and global capture, with both providers. Owner tests separately kill three numerical evaluations to prove the spent budget survives restart. Recovery preserves occurrence, original time/deadline, owner revision and exact outcomes. No reservation is refunded or clock retimed. The expired native test observes a committed adjustment while refusing missing visibility/native success. Owner outage after capture prevents context delivery; restoring availability releases the same capture.

Context preparation also retains spent attempts and its original deadline across repeated native interruptions. A fresh application process may exhaust the 30-second deadline before all three preparation attempts can run. That is an explicit failed/pending outcome, not permission to renew a deadline or create a new context identity. Both the first over-specific experiment and its corrected bounded-outcome check are retained. These guarantees assume intact local files and a trusted host; journal loss, power-loss certification and malicious-host recovery are not claimed.
