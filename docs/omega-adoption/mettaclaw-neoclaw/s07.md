# S07 — bounded native model-completion adoption

**The bounded S07 integration is demonstrated, with failures retained. All twelve authorized generation attempts were spent.** Ten responses were durably captured. Three complete workflows combined real isolated IRC, actual native Omega dispatch, original NAL deduction, its result in the next model input, and an approved reply observed by the separate socket peer. Both local and authenticated same-host HTTPS model placement passed. Two real native process kills recovered the original captured occurrence without regeneration.

This is a controlled text-completion integration, not reliable autonomous command generation or full default Omega. Two captured replies proposed unsupported command names; both were rejected without sending. Earlier attempts include one original-deadline timeout and one adapter-validation failure. No failed occurrence was retried, refunded, retimed, repaired or silently replaced. The user's later instruction to use all twelve calls authorized the remaining predeclared independent trials.

## Responsibility and adopted boundary

```mermaid
sequenceDiagram
    participant IRC as Isolated IRC / durable Messaging
    participant App as Native Omega + application journal
    participant Model as X01 completion owner
    participant Ollama as Pinned local Ollama CPU runtime
    participant NAL as Existing S01 native NAL
    IRC->>App: Durable message occurrence and input deadline
    App->>App: Commit exact prompt, TIME, source and slot
    App->>Model: Bound completion, local or authenticated HTTPS
    Model->>Model: Independent acceptance and one reservation
    Model->>Ollama: One selected text-generation request
    Ollama-->>Model: Text and observed accounting
    Model->>Model: Validate and capture independently
    Model-->>App: Bound retained result
    App->>App: Capture before native parsing and whole-batch authority
    App->>NAL: Approved original Truth_Deduction
    NAL-->>App: Actual native result
    App->>Model: Next input includes actual COMMAND_RETURN
    Model-->>App: Captured reply proposal
    App->>IRC: Approved send; separate acceptance, write and peer observation
```

The application owns prompt assembly, occurrence identity, native parsing and command authority. X01 owns generation reservation and response capture. The adapter maps only the selected Ollama request/response. C1/C2, Attention, Search, AtomStorage, the existing S01 execution owners and S06 Messaging retain their responsibilities. A completion is neither new empirical evidence nor a belief/priority update.

`model.inference/1.0.0` exposes `complete`, retained `observe` and current `authorize`. Fresh `controlled-native-loop/9` compositions select `neoclaw-ollama-qwen38-text/2`: five minutes per newly accepted input/model occurrence. The historical `/1` profile remains thirty seconds, with byte-identical descriptor, limits and model options. The failed `/1` occurrence remains spent at its original deadline. Existing tool/context-preparation deadlines stay thirty seconds. No populated journal changes profile.

Both model profiles use the same pinned weights, native `_chat`/`_clean` transformations, temperature/options, 32,768-token context, 6,000-output-token ceiling, disabled thinking/streaming/truncation/drafting, and one generation reservation. Five minutes accommodates the measured short command workflow; it does not promise completion of 6,000 generated tokens. Native loop, parser, skills and successful presentation remain real. The selected synthetic scaffold intentionally exposes only the original `metta` and `send` descriptions. No prompt or sampling change followed either live semantic rejection.

The shared endpoint was busy with unrelated work before fresh admission. A load-only timeout and a deliberately interrupted readiness wait consumed zero generation reservations. A temporary loopback instance then used the same verified executable and existing blobs, with cloud disabled and the user's home masked. Its selected port and manifest were bound through the runtime lock and application configuration. HTTPS callers could not open the model assets or connect to that raw backend port. Existing services were untouched; the temporary listener and children were stopped after call twelve.

See [contract decisions](s07-contract-decisions.md) for exact bounds, ownership, disclosure and compatibility.

## Changed files, guarantees and limits

New implementation: `fusion/model_contracts.py`, `model_service.py`, `model_transport.py`, `neoclaw_model.py`, `neoclaw_model_disclosure.py`, and the Ollama/native-text adapters. Narrow changes integrate them with the existing application, channel acceptance, native startup/loop bridge, memory bootstrap and HTTPS host. Integration files provide the original-source oracle, selected composition, fresh synthetic corpus, bounded campaign and separate recorded-model host. Test actors gained bounded longer lifetimes while keeping historical defaults. Tests, exact source manifests, evidence, adoption ledgers and runbook accompany these changes; the final source-state file enumerates every changed path and hash.

Observed guarantees are independent acceptance/reservation/capture/command commits, one backend reservation per occurrence, exact retained replay, current authorization, complete prompt binding before generation, capture before command admission, no automatic fallback/regeneration, and unchanged historical numerical/ownership profiles. This does not establish exactly-once upstream execution, billing, cancellation or IRC delivery. The model failed to obey the command vocabulary twice; authorization, rather than model compliance, prevented effects.

No required prerequisite remains blocked for this bounded demonstration. Full historical suites, production reliability, live default Omega/model-channel startup, populated private context disclosure, paid/hosted/vision backends, multi-host, migration and chain are unrun or explicitly outside scope. Temporary journals were exported then cleaned; published evidence is not a reusable live database. Only X01's selected text operation is marked adopted. The historical fifteen families, 105 mapping rows, eight prior operation adoptions and nine native user commands remain unchanged. No further generation is authorized by the exhausted twelve-call budget.
