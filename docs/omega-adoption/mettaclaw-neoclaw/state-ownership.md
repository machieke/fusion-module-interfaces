The most consequential shared-owner violations are semantic, even though a single process currently writes them:

1. `remember` combines payload persistence, vector enrollment and provenance-like linking. There is no accepted source event from which another Search provider can reconstruct the same index.
2. `tvUpdate` modifies Relations and belief metadata without an evidence ledger. A duplicate episode string is suppressed in the list but its numerical effect is applied again. Chroma metadata read-modify-write also couples link and truth writers; concurrent writes can lose changes.
3. `update` spans new Chroma records, old deletion, links, promotion SQLite and truth. No owner can attest an atomic replacement. Static ordering plus the wrapper fixture show the old truth lookup occurs after deletion and returns `None`; full native update remains unrun.
4. `query` reads vectors, scores, links, truth and content at different moments. Neither a consistent snapshot nor freshness can be inferred from one displayed result. Global promoted-context selection is a separate path from vector-candidate reranking.
5. The loop receives before durable history, executes effects before history, and exports executable state afterwards. A single success token does not close all of these effects.

A future facade must own only **request/correlation and compatibility state**, not copies of authoritative belief, attention or relation databases. Each module owns its journal and acceptance receipts. The facade must recover by ports and recorded identities, never by reading another owner's SQLite tables or the old Chroma files. This task defines no migration for populated stores.

All private text, embeddings, STVs, episode links, prompts, images, stable identifiers and payload hashes remain private by default. Even a derived vector or hash may identify a private item. Only deliberately generated synthetic/public inputs qualify for the proposed first remote trial; no chain placement is proposed.
