# S06: real isolated IRC through durable module handoff

S06 adopts one IRC receive boundary and bounded native `send` under
`isolated-irc-mailbox/1`, selected by fresh `controlled-native-loop/8` composition.
The actual native Omega loop consumes input from a real isolated ngIRCd server
through immutable AtomStorage and durable Messaging. A separate socket peer
observes the approved outgoing reply. Local and authenticated same-host HTTPS
mailbox placement use the same native application logic. This is controlled
native integration with a scripted external model, not full live Omega startup.

All eleven required gates pass for this bounded profile, with no remaining
prerequisite blockers. The [gate manifest](../../../evidence/s06/verification.json),
[run accounting](../../../evidence/s06/run-results.json) and
[source reconciliation](../../../evidence/s06/source-reconciliation.json) specify
which bytes and scenarios passed. The starting checkout was exactly
`c9c6e7985c8214feeedc78686f475efb3ad40625`, with only the untracked S06 brief.
Before edits, all 247 S05 tested hashes, 35 final non-evidence hashes and 141
evidence hashes matched. S05's historical working-tree test identity on
`0d66b4b8f404450367a711de905f4a251f4b0255` remains unchanged.

## Responsibilities and changed semantics

| Owner | Responsibility | Explicitly outside its guarantee |
|---|---|---|
| IRC bridge | Connection epochs, ordered durable capture, relay progress, outbound intent and one socket reservation | Native turns, belief interpretation, IRC history recovery |
| AtomStorage | Immutable canonical scoped envelope and verified payload bytes | Mailbox progress or external delivery |
| Messaging | Durable ref acceptance, ordered poll and acknowledgment, capacity reuse | Recipient receipt or completed model/tool work |
| Application | Durable input-to-slot assignment, command occurrence, result and next-context handoff | Socket ownership or foreign journal reads |
| Local C1 | Actual transport observation tied to channel occurrence | Verified human identity, truth, independent empirical evidence |
| Local C2 / Attention | Existing beliefs, priorities and retained views | Channel queues, evidence weight from acknowledgment, vector rebuilds |

The new profile composes the existing `atom.storage@1.0.0 / immutable-bytes/1`
and `agent.messaging@1.0.0 / durable-mailbox/2` ports. It does not widen their old
schemas or expose execution through the channel endpoint. Closed envelopes bind
scope, route, session, bridge, epoch, order, occurrence, time and exact text;
requests bind principal, descriptors and correlation. Current authority applies
to effects, cached reads, acknowledgment and native result release. Payload,
mailbox and acknowledgment keys are stable, including `ack/<delivery>`.

Capture allocates identity and pending relay in one bridge transaction. Equal
text in separate IRC frames has different occurrence IDs. An application commits
the complete input envelope, delivery and processing slot before acknowledgment;
retries retain that assignment. The native new-input predicate uses that identity,
while native single-message rendering and escaping remain intact. The old volatile
concatenated buffer becomes one admitted message per slot. Before accepted model
response, generation can repeat; accepted command positions resume independently.

Native `send` now returns `SEND-ACCEPTED` after payload/mailbox acceptance. It
updates `lastsend` only from accepted state. This deliberately replaces legacy
unconditional `SEND-SUCCESS`. Only explicitly approved synthetic text already
within the original single-chunk domain is admitted. Controls, multiline/wrapped
output, excessive UTF-8 bytes, private canaries and their identifying hashes fail
before any outbound storage or authorization call carries those bytes. This allowlist is not a general
model-output declassification system.

The bridge commits its egress intent before mailbox acknowledgment and reserves
one socket attempt before writing. The independent facts are acceptance,
reservation, write-returned/known rejection/unknown, and peer observation. A kill
after reservation can leave a spent `unknown` even when the peer saw the first
write. Recovery never automatically sends again, refunds a reservation or changes
a deadline. Two intentional identical sends in different positions remain two
occurrences. The [contract decisions](s06-contract-decisions.md) define all bounds
and outcomes; the [architecture](../../module-interfaces/architecture.md#s06-actual-irc-at-the-controlled-native-boundary)
shows owner dependencies.

all six mailbox handoffs are acknowledged independently.

[Empty-poll interruption](../../../evidence/s06/candidate-01/native-empty-budget.json)

[real provider kills](../../../evidence/s06/final/provider-kills.json) interrupt

[Capacity evidence](../../../evidence/s06/final/capacity-discontinuity.json)

authority is restored, without another send. Revocation does not retroactively
cancel already accepted external work.

## Placement, privacy and test classes

The real server binds only `127.0.0.1`, with passive mode, no federation and no
public/native default channel. Evidence inspects the running server's actual
listener descriptors. The independent peer only opens a socket and records its
own traffic; it does not populate application or owner journals. IRC uses isolated
TCP, while the separately placed AtomStorage/Messaging leg uses verified HTTPS
with distinct bridge/application credentials and a generated pinned CA.

The HTTPS caller lacks provider configuration and cannot open provider/bridge/server
stores through its tested filesystem masks. Bridge and provider masks hide local
application, model, C1/C2 and Attention stores. Native startup rejects the legacy
IRC module and tests a direct IRC socket refusal. The selected Python audit hook
allows only the mailbox HTTPS endpoint. Linux 5.4 lacks the attempted Landlock
facility: this is a source-checked trusted-runtime guard, **not an OS network
sandbox or malicious-host isolation guarantee**. No full live Omega or public
network connection is exercised.

## Accounting, corrections and limits

There are 25 distinct S06 methods: twelve contract methods, seven real bridge
methods and six native-loop methods. The final report counts the original oracle
as an executed program, not another unittest method. Parameterized placements,
eight native input/command kill scenarios, eight bridge handoff/effect kill
scenarios, two provider kills, and the separate budget/disconnect checks do not
inflate those method counts. The selected historical regression union is 151 distinct methods (176 combined
with S06), recorded separately in the run manifest; neither repeated runs nor baseline overlap is
counted twice.

The broad native matrix used candidate-01. Later targeted changes added current
authority at native result capture, bounded stable acknowledgment keys and cleanup
for refused bridge initialization. Final bridge/contract rechecks, both native
placements, explicit revocation recovery and two-position result-kill recovery
exercise those changes. A final operator-helper correction uses atomic policy-file
replacement and repeats contract/current-authority and real provider-kill tests.
Per-run source manifests preserve these distinctions; no historical run is
relabelled as the final whole-tree run.

Development failures remain recorded: a configure command used the wrong working
directory; a listener probe raced a closing descriptor; buffered peer stdin hid
burst commands; process-parent exit briefly preceded lock release; a Python import
name collision selected the historical channel fixture; and a context assertion
ignored native `_quote_` escaping. The original oracle initially used an overlong
nick prefix, then a JSON `\\u` escape produced the literal `u03a9` on the wire;
literal UTF-8 fixed the driver without changing native code. An early comparison
started before its oracle artifact existed. A broad caller revocation also removed
the bridge route prerequisite and timed out awaiting receipt; the focused release
test now revokes the intended read permission. A historical import-boundary guard
failed after C1 tests contaminated the interpreter and passed in its required fresh
process. Failures and observation timeouts are separate from prerequisite blockers.

Guarantees assume intact owner files, a trusted local host and the declared clocks.
There is no cross-owner transaction, power-loss certification, durable IRC history,
exactly-once upstream capture or external delivery, recipient ACK protocol,
automatic reconnect/history scheduler, safe arbitrary output declassification,
existing-journal migration or remote private cognition. Conservative original
deadlines can exhaust before recovery completes. Read-only observation of retained
outcomes does not authorize a fresh socket attempt.

The [runbook](../../module-interfaces/runbook.md#s06-fresh-isolated-irc-recipe)
provides the source/build/start/test recipe. [Changed-file hashes](../../../evidence/s06/source-state.json)
and [tested source](../../../evidence/s06/test-source.json) identify the delivery.
The historical 105-component mapping and fifteen-family denominator are unchanged:
