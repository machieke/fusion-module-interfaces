# Retrieval workload preparation decisions

These are implementation choices for the assigned generation-disabled preparation,
not retroactive S07 behavior or past meeting decisions. The starting publication
is `367c9b583eb85d6cf99ca93827c9f40b9c681bc6`, whose sole predecessor delta after
S07 `4981788b4d8069a2b2264e65197f9886b74f1f5f` is the published 17-file closeout.
The closeout packet and its historical source/test identities remain authoritative.

## Selected composition and authority

`controlled-native-loop/10` selects `synthetic-retrieval-query-send/1` disclosure
and admission. This is an application composition, not another module, numerical
profile, tool language or execution service. `model.inference@1.0.0` and
`neoclaw-ollama-qwen38-text/2` are unchanged. Historical `/9`, its numeric feedback
policy, and model `/1` remain separate, closed selections.

Exactly one native parsed command is allowed per model occurrence: slot 1 is the
one operator-selected `query`; slot 2 is `send` with one of at most eight distinct,
exact harmless bodies. The complete batch is checked before accepting a command.
The original native parser, balancing and rendering execute; no proposed command
is repaired. Permission to publish a candidate body does not assert that it is
true. An independent evaluator scores the actual retrieved result and peer receipt.

Setup executes three native remembers against an initially empty authoritative
source. Setup's selected ready view is composed into a fresh measured application
journal and session, with no setup turn history. This is fresh-session composition,
not journal migration. Immutable storage, named Search publication, local metadata
readiness and native success remain separate observations. The generated defaults
retain `neoclaw-fresh-memory-compatibility-prior/1:not-registered`; no empirical
observations or historical provenance are invented.

The measured application retains existing read-view machinery, but setup write
and memory-encoder permissions are revoked before it starts. Its model batch
policy admits neither remember nor assessment/promotion commands. No operator
policy edits occur between the healthy query and reply. Test failpoint selection
and revocation injections are explicitly separate from healthy composition.

## Disclosure receipt

The trusted application approves exact generated payload content, identity,
creation label, links, compatibility prior and STV presentation for a named
recipient. It checks these against its own retained read capture and the existing
owners' current authorizing reads. It does not read another owner's database.
The whole native projection, record order, source snapshot and retained view stay
bound. The selected domain refuses section delimiters, quote/placeholder injection,
newlines and fake tool syntax in record text instead of silently redacting it.
The native list representation's apostrophes undergo the pinned native
`string-safe` transformation; no expected answer is inserted into feedback.

Before releasing a prompt, the trusted sender reads the same operator-owned
`Policy` that the model owner uses, checking current principal, disclosure and
operation permission, session, selected descriptor and recipient. Its policy
directory is mounted read-only in the native caller. This is a same-host
authorization read, not a copied permission cache or a foreign journal read. The
owner independently checks again on receipt. Revocation before this preflight
stops the prompt before even an observe/authorize HTTPS body is sent; concurrent
revocation can still race the network transfer and is rechecked at the owner.

Before a model request, the application durably publishes an immutable disclosure
receipt binding the entire completion intent, selected recipient, consent seal,
context view and (for slot 2) query occurrence, view, result and capture digest.
The model owner independently checks this receipt plus current authenticated
permission. The fixed view is in the sealed disclosure selection. A model command
cannot issue a receipt or choose its path. The provider receives the actual prompt
and receipt, without access to the corpus, index, evaluator or caller journals.

Receipt files are a narrow trusted-local handoff, not a new cross-domain signature
scheme. The issuer and composition are trusted. In the HTTPS test placement the
provider sees the receipt directory read-only; its own database is separately
writable. Local evaluation also runs in a restricted subprocess. Local owner code
still shares the existing application's trust domain. This does not claim resistance
to a malicious host administrator or tampering by the trusted issuer.

## Placement and fixtures

The combined workload fixes memory retrieval and E5 encoding locally and uses
local C1/C2/Attention plus an authenticated same-host HTTPS mailbox. Only model
placement changes between local and HTTPS. The existing private cognitive profiles
still reject remote memory placement. Separate `/5` native remember/query parity
checks exercise real HTTPS retrieval and encoding with an E5-free caller; they do
not establish remote private cognition or a combined private-memory HTTPS profile.

Every completion in preparation is explicitly authored. Its fixture necessarily
contains its proposed reply; that is a declared test input, not evidence of a
generative model choosing an answer. It may propose commands
but cannot supply retrieval feedback or inspect the evaluator/corpus. The existing
model owner still performs independent acceptance, reservation and capture, and
the application independently captures and admits the response. Failure to select
a real backend never selects this fixture. The controlled test launcher selects
it before execution, with a namespace check; the live plan has no activation path.

Real dependencies are the pinned native loop/parser/remember/query/getContext,
E5, Chroma, DeTTa, isolated ngIRCd and socket peer, and authenticated loopback HTTPS.
Creation and attention clocks, controlled empty history, responses, and fault
injections are fixtures. Empty global context is produced by the owned Attention
read over unpromoted generated memories, not an answer-bearing context fixture.

## Budgets and limits

Existing model/input bounds remain 300,000 ms, tool/context bounds 30,000 ms,
eight application model RPC reservations and one owner evaluation reservation.
Encoder/read budgets and S06's one reserved socket attempt remain unchanged.
Recovery observes already captured artifacts and rechecks authority; it does not
extend deadlines, refund budgets, reconstruct a result by querying again, or
resend after an uncertain socket outcome. IRC loss before durable bridge capture
and unknown recipient delivery remain outside the guarantee.

The preparation launcher creates a new network namespace and masks known
text-model executables/assets and service managers. An owned host listener and
masked-executable tests verify denial before qualification. It never probes a real
generation endpoint, starts Ollama, loads its model, or contacts a public network.
This isolation is for the bounded qualification; it is not a general hostile-code
sandbox or a claim about unrestricted default Omega startup.

The proposed live campaign stays disabled: two sessions, two calls each, 6,000
output tokens/call, the existing deadlines and no replacement attempts. New user
authorization must bind a frozen plan. None is issued or inferred by preparation.
