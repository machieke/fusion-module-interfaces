# S05 contracts and regression impact

The selected fresh composition is `controlled-native-loop/7`. Historical `/1` through `/6`, STI and NAL/PLN profiles keep their meaning. Attention version 3.0.0 selects `wall-clock-promotion/1`, resolving the mapping packet's draft. This is local private state; no network placement or populated-state conversion is supported.

Attention owns value/time pairs, complete retained revisions, immutable bound clock/read identities, spent numerical evaluation reservations and exact receipts. Application owns turn/position occurrences, alias resolution, corpus/belief views, visibility and native/context captures. AtomStorage owns content and the authoritative enrollment feed. Search owns its index. C1/C2 remain independent owners. No attention operation accepts memory text, beliefs, executable code or an arbitrary numerical function.

`bind` accepts an authenticated principal, descriptor selection, policy, scope/context, occurrence, kind, bounded eligible UUID list, delta, deadline and limit. It samples the trusted local epoch clock once and binds the current owner revision atomically. `adjust`, `scores`, `rank` and `observe` require that exact owner binding. A retry recovers it; it cannot choose a new clock. Effect identity has no transport-key component. `observe` returns an existing receipt after expiry without constructing missing work. There is no automatic CAS retry. A competing commit requires explicit conflict handling, not a new occurrence or clock. A later read alone does not cancel or retime an already bound adjustment: it can commit only against its original still-current revision, using the original time. Any intervening mutation makes that CAS stale.

The clock high-water mark covers newly bound work in each principal/scope/context, including read bindings. Tolerance is zero seconds; equal and fractional samples are legal. Backward samples fail. Already bound historical reads retain their revision/time even after newer work. Read preparation writes clock/work receipts, not promotion values. The policy's epoch clock and actual invocation deadline are distinct. Test clocks are declared operator fixtures; model arguments cannot select time.

The pure numerical dependency extracts the original pinned `get-promotion` expression and exact promote/demote cap expressions. It executes them under the existing PeTTa/SWI 10.0.1 recipe without importing NAL. Its validator requires the pinned interpreter `src/*.pl`, native memory source and existing binary/library hashes; it also works with NAL and PLN library files absent. The full native loop keeps its separate complete-source checks. Finite binary64 values in [0,10], finite nonnegative epoch samples no greater than 2^53, and nonnegative elapsed time define the admitted domain. Invalid values fail rather than being repaired. Missing target state in an existing selected revision has the native zero default; missing bindings/revisions fail.

Bounds are 128 opaque UUID targets per context/request, eight contexts, 256 bound work identities and 256 revisions, three native evaluations per identity, and one bounded numerical batch per attempt. Receipts/revisions are retained with no eviction or garbage collection. Context preparation has three durable attempts per accepted iteration; it does not obtain a new deadline/budget on restart. Native commands reuse the existing application turn/occurrence capacity and 30-second deadline. A file provider is an independent storage fixture, not a migration path.

Query retains native candidate sorting `(-score, distance, uuid, ...)`, promoted prefix, merge, uniqueness, limits and rendering. The adopted score port returns every candidate, including zero. Global rank is independently complete over the authorized selected corpus view, with native `(-score, uuid)` order and positive filtering. Authoritative enrollment is read through AtomStorage's bounded commit feed, not a foreign database or a Search query. Selected content is hydrated and verified in rank order through AtomStorage. Labels/STVs use the retained S04 presentation. The private promoted-memory output is derived from a captured native rendering and replaced atomically; deleting it does not change owner state.

Native `promote`/`demote` use a single argument containing spaces; unlike support/contradict they do not replace underscores. Missing/ambiguous aliases now fail before effects, instead of silent success or fan-out. At cap/floor an intentional new occurrence still commits its time and receipt. Query and global capture release recheck current owner, content and belief authority. Outage is an error, never zero scores or an empty-context fallback.

The baseline reconciles all S04 tested/final/evidence hashes without rewriting historical identities. Impact-selected baseline: S04 pure math, owners and actual loop (21 methods), historical M3/M3.1 Attention plus delivery/compatibility (14 methods). Final coverage adds the affected S03/S03.1 embedding/query and S03.2 append/retained-view HTTPS tracks, application/S01/S02 source guards, and S04 plus historical Attention again. Live web, chain, full Omega, multi-host and remote private cognition remain outside this increment. Per-run outputs and final method accounting are recorded separately; this is not a claim to run every repository test.
