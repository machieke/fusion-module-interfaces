# Current native capability matrix

This maps the **twenty registered native tool descriptors** in
[`preview_capabilities.py`](../../fusion/preview_capabilities.py) and
[`preview_tools.py`](../../fusion/preview_tools.py). It is a command/ownership
matrix, not another inventory of the historical fifteen module families.
Registration does not grant a session permission or establish integration.

The historical mapping denominator remains **15**, with **8 adoption entries**
and **9 historical native user commands**, as recorded in
[`coverage.json`](../omega-adoption/mettaclaw-neoclaw/coverage.json).
The twenty preview descriptors use a different denominator. **X01
ModelInference** and **X02 Embedding** remain separate extension entries;
**X05 ToolDescriptor** describes the catalogue contract. None increases the
historical family/adoption counts.

## Admission and ownership

Every row is operator-selected, scoped to fresh synthetic data and checked
against current session and provider authority. The native parser proposes a
whole batch; an unauthorized command rejects that batch before tool dispatch.
Typed handles identify exact scoped targets and grant no authority. Provider
descriptors, versions and profiles must match the selected composition; no
fallback is implied. Original accepted occurrence identities, retained views,
deadlines and spent budgets survive recovery.

The owner column includes actual composition dependencies, not just the direct
requirements listed on one ToolDescriptor. For example, a cognitive native query
also uses current Attention, retained C2 beliefs, C1 provenance and structural
labels while preserving their separate owners. Each service retains its own
journal/PVC; caller metadata is a derived presentation, never another owner's
authoritative database.

## Internal seams are not additional native commands

The session service (`omega-native-sessions/2`) owns durable input acceptance and
completion. `PreviewModel` uses the recorded-only ModelInference owner lifecycle;
the model fixture proposes commands, while real native dispatch and selected
owners execute tools. X01 is not a new model-generation pass in this programme.
X02 independently places the existing E5 query/append encoders; it is not another
Search implementation or another native command.

Task-result publication/ingress and application acknowledgment are internal
transitions, not model tools. Exact chain registration/approval/commitment is an
operator-authorized ConsensusFinality path, separate from `inspect-atom`.
C19 uses the exact D19 generated artifact and inspection result. Its separate
approval, saved signed intent, matching deploy-effect finality and independent
readback passed, including lost-response and replacement recovery with zero
automatic resubmissions. The [historical dev17 chain report](../../evidence/phase2/development/final-dev17/same-workflow-chain.json)
retains its own artifact and source identity. The session API does not establish
another IRC-channel pass. Historical external web search and channel/send
adoption are not implicitly added to this twenty-tool catalogue.

This preview excludes arbitrary execution, live text generation, physical
erasure, populated-state migration, private-memory export, recursive delegation,
general planning/search, new numerical rules, multi-node deployment and public
chain work. `ADDITIONAL_LIVE_GENERATIONS=0`.
