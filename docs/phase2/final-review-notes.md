## Scope and usability limits that must remain explicit

- **Private scopes:** generated A/B private AtomStorage scopes are distinct
  and authority checked. Native memory/cognition/history in the combined
  composition use the approved shared synthetic scope. C1 principal checks do
  not make its underlying shared atoms confidential. No private cognitive
  remote-placement claim follows from the private storage denial tests.
- **Provider compatibility:** the SDK executes archived/development client and
  independent file-provider packages over real HTTPS. Package versions
  `0.1.0`/`0.2.0` retain the same storage wire/profile; this is additive package
  interoperability, not numerical compatibility or populated-state migration.
  The unchanged `save_and_consume` sample is an adapted caller, not native
  Omega. The separately executed Attention replacement is the native-consumer
  substitution gate, with fresh provider state and an explicit fixture-provider
  label for the independent atomic-file implementation.
- **Workbench:** `preview_workbench.project` groups captured, authorized
  SessionStore results. These panels are retained observations, not independent
  live reads of every lifecycle/C2/Attention head. Current session authority,
  selected catalogue and workload readiness are checked separately; chain
  observation is an explicit action. Do not describe refresh as revalidating
  every displayed historical cognitive value against current owner state.
- **Sessions:** API creation opens operator-preselected templates; it does not
  authorize arbitrary model-selected principals, policies or endpoints. Failed
  or expired accepted work retains accounting. It can block a session's oldest
  incomplete input; pause/resume does not renew it or silently skip it. There
  is no general scheduler or automatic replacement task.
- **Lifecycle:** immutable successor selection, publication and application
  visibility are separate. The lifecycle receipt holds exact predecessor and
  successor refs; the native result exposes successor/logical revision, linked
  to the accepted predecessor handle. Withdrawal blocks active disclosure but
  does not erase earlier bytes, evidence, backups or captured outputs.
- **History:** external-effect observations describe what was observed, such
  as durable mailbox acceptance. They are not recipient execution, IRC delivery
  or chain finality unless the separately owned observation says so.
- **Resources:** the fixed repeated-turn envelope is a bounded sample, not an
  SLA. The AtomStorage/feed owner has an aggregate **512-record** cap, including
  administrative history, event/payload records and chunks across its scopes.
  The 24-input per-session limit is an admission ceiling, not a promise that
  four sessions can each finish 24 inputs. The workbench unpin failure exposed
  this bound; it was not raised or reset. Preserve cache conditions and actual
  per-stage timings. Application caps do not establish host CPU-quota
  enforcement. Hosted CI remains unobserved unless a hosted run is inspected.
