## 4. Track A — provenance and sustainable control-plane state

### V01 — resolve the historical adapter guard, without erasing history

Reproduce `tests.test_neoclaw.S01Contracts.test_existing_numerical_sources_unchanged` on the supported interpreter and actual starting tree. Trace the full-file DeTTa adapter hash change through available Git history, prior manifests, approved modifications and executed behavior. Identify which changes are numerical, storage-semantic, packaging/validation or unrelated; do not assume the test name describes every file it covers.

Separate three assertions: historical snapshot integrity; current selected implementation identity; preservation of the required behavior. A historical source pin belongs to its historical snapshot. A current adapter has its own reviewed identity and compatibility obligations. Implement explicit manifests/tests for those distinctions rather than automatically refreshing expected hashes.

Retain negative tests: deliberately altered numerical source, an unapproved adapter identity, weakened persistence/replay behavior and a genuinely nonconformant provider must still refuse. Run actual affected DeTTa reads/writes/restart and source-check paths. Do not resolve this by skipping the test, removing the protected file, widening every allowed hash or claiming behavior tests establish historical byte equality.

**Exit:** a technically explained current green guard/compatibility path and intact historical evidence. If exact historical provenance is inaccessible, provide that narrow unresolved fact, block any unsupported compatibility claim and continue independent work. A missing narrative is not permission to waive a demonstrated runtime regression.

### V02 — normalize provider selections without changing accepted meaning

The Registry currently retains complete records in action intents and session bindings. Measure repetition on the actual sustained workload before redesigning its representation.

Add a fresh explicit representation using immutable, owner-controlled provider/requirement/selection objects and small references where bytes really repeat. Preserve every accepted action, exact selected version/profile, implementation identity, numerical/privacy guarantee, consent/actor binding, original observation and audit result. A checksum used as an internal key is not authority; current policy still runs.

Preserve canonical encoding and the distinction between an unordered conjunction of requirements and an ordered preference list. An equivalent current configuration may select the same meaning, but old signed/bound request or response digests must not be recomputed over normalized bytes and called unchanged. Retain their original wire bytes or an exact reconstruction layer where promised.

Use the same session/Registry owner transaction to publish a referenced selection with its session binding; do not create another registry service merely to share JSON. Bound object counts, byte totals and reference depth; detect missing/corrupt objects. History/profile readers stay strict.

**Exit:** an equal-workload comparison of baseline versus normalized metadata bytes, identical reconstructed old selections, actual native use and conflict/refusal tests. Increasing the one-MiB limit alone cannot pass this package.

### V03 — sealed Registry history and reserved control capacity

Implement finite audit epochs or another owner-controlled retained representation so normal readiness/action history need not occupy one ever-growing active JSON working set. Keep accepted bindings and replay identities reachable. The current projection may be rebuilt from sealed history plus its head; sealing does not delete logical audit facts or reset lifetime accounting.

Reserve bounded space at admission for finishing an accepted action and for required disable/drain/reconcile observations. Maintenance must not require more normal admission space than remains when it is needed. Define maximum epoch size/count, open actions and total retention. A full retention limit still refuses honestly.

Rollover follows a durable plan: record identity and source head; write/verify a sealed segment; atomically activate its mapping; recover uncertain publication by observation. No checkpoint advances beyond reconstructible state. An unknown readiness probe stays unknown and spent; rollover must not re-probe or refresh validity.

Keep sessions tied to original provider selections across sealing, disable, restart and archive reads. Readiness renewal is a new bounded observation, never a replay that lengthens an old time window.

**Exit:** real Registry use beyond the old equivalent one-MiB representation, with explicit finite new limits, intact old reads/receipts, interrupted rollover recovery and refusal at a small configured ceiling. Do not bypass the Registry during the acceptance run.

### V04 — complete owner headroom and honest admission

Extend the existing headroom interface across owners used by the pilot: session/Registry, storage/feed, C1/C2, Attention, Relations/lifecycle, Search generations, Messaging/outbox, execution/continuation, workspace and model accounting. Reuse existing observations rather than introduce a central quota database.

Each response identifies observed revision/time, unit, hard bounds, charged/retained usage, outstanding reservations, reclaimable derived bytes if known, and emergency/control reserve. Unknown remains unknown. Do not mix records, bytes, sessions, attempts and generation permission into one percentage.

Expose owner-specific admission checks and a conservative application estimate for common workflows. An estimate is not an atomic multi-owner capacity promise. If a later owner refuses, preserve the original operation and partial commits; do not compensate by deleting evidence or retrying under a new identity.

Maintain readback, current-authority checks, cancellation of unstarted work and exact result reconciliation near normal-admission saturation. Administrative traffic itself has bounded resource accounting and cannot be abused to bypass the cap.

**Exit:** boundary tests for each active owner, accurate private-scope headroom denial, normal-overload plus successful authorized saved-result observation, and clear UI/CLI capacity units. No fabricated lifetime counts for owners that cannot supply them.

### V05 — operational windows without reset

Use existing commands and contracts, not a background orchestration system.

Freeze a small finite maintenance schedule before qualification. Ordinary provider probes, session closes, archival actions and UI reads must not themselves grow control state without bound. ## 6. Track C — bounded failure behavior during ordinary use

### V11 — admission lanes and reserved reconciliation capacity

Introduce explicit bounded concurrency/queue lanes inside the existing relevant owners: ordinary new work; finite maintenance; read-only observation/reconciliation. This is not a separate scheduler or broker and does not grant priority classes arbitrary resource access.

Keep one authoritative writer per journal. Define finite per-actor/session inflight and pending limits, fair selection at committed boundaries, and capacity needed to finish already accepted receipts. A long-running E5 or native task cannot monopolize every observation path. Equally, flooding status requests cannot create unbounded diagnostics or starve legitimate mutations.

Cancellation, drain and result observation remain scoped and current-authorized. A reconciliation lane may read old committed results after execution expiry; it cannot execute missing steps or refund work. Use explicit typed overload/retry-advice fields only where they fit a selected profile, without enabling invisible SDK retries.

**Exit:** resource-limited native tasks produce honest backpressure while saved-result/status/cancel-before-start operations remain usable; two callers receive bounded fairness; queue saturation survives restart with unchanged original deadlines. Report observed bounds, not an SLA or replacement for kernel quotas.

### V12 — asymmetric network failures and retry audit

Audit the actual retry points from installed Python/Go/browser clients through pooled HTTPS, service adapters and backend SDKs. Produce one machine-readable retry classification for each exercised operation: safe read retry on fixed view, idempotent replay under original identity, observation only, or prohibited automatic replay.

Inject real task-scoped disconnects/connection resets and isolated network-policy faults: caller reaches provider but cannot read reply; provider reaches storage but not Messaging; name resolution failure; delayed reply from a replaced pod; partial bounded body; connection retained across credential change. Do not modify host-wide networking or use a fake provider to claim a real loss boundary.

Track physical sends separately from logical attempts and owner acceptance. Transparent library retries must be disabled or accounted within original bounds. A failed readback is not proof of absent acceptance. Restore connectivity without changing the accepted endpoint, principal, model, scope or view.

**Exit:** installed clients recover or truthfully refuse according to the operation's policy, with no duplicate logical write, model reservation or uncertain external send. Explicitly report effects not observed rather than deriving them from TCP success.

### V13 — time discontinuity, suspension and expiry

Specify how selected contracts use epoch time versus monotonic elapsed time. Preserve native wall-clock promotion and historical policies. Add test clock seams at contract boundaries; do not change the host clock.

Exercise forward jump, backward jump, long pod suspension, approval expiry, delayed observation and deadline equality. A new invalid time sample cannot increase priority or prolong an accepted operation. A resumed captured result retains its original clocks and can be observed only under the current disclosure policy. Diagnostic collection can time out independently of business execution without silently cancelling or reissuing it.
