## 0. One larger outcome, not another sequence of narrowly scoped handoffs

Deliver a usable, measured, recoverable **single-node Omega service-platform release**. It must make the original service-handoff objective practical: a native Omega uses selected implementations for storage, retrieval, cognition, communication and bounded execution; developers can change allowed placement and compatible implementations without rewriting the agent.

The release must support repeated interactive use, durable asynchronous task handoff, explicitly bounded multi-step continuations, independently developed clients/providers, retained knowledge and history, inspectable failures, and an approved isolated-chain commitment from an actual native workflow.

This programme **REPLACES** `codex_omega_phase4_interactive_execution.md` as the primary backlog. It includes all T01–T12 obligations and substantially expands the delivery. The old file is a supporting specification, not a second list to execute and not an intermediate approval checkpoint. Phase 2 and Phase 3 are completed baselines to reuse, not new tasks to reimplement.

### Concrete end state

An operator installs from declared artifacts, creates two native agent sessions, selects an approved local/pod service composition, submits bounded work without editing source, observes real native progress, hands a typed task to another executor, resumes from saved results after interruption, archives and reads authorized old records, and diagnoses or safely reconciles blocked work. A second-language client and an independent provider demonstrate that the contracts are not coupled to the original Python/native composition. The same system can commit one explicitly approved synthetic result to its isolated chain adapter.

Model responses remain recorded fixtures during this programme. They may propose commands; they may not execute tools, supply expected numerical results, fabricate retrieval feedback, or read evaluator answers. This release is **not** a claim of autonomous model competence, production security, multi-node operation, general process migration or on-chain reasoning.

### Working agreement

- Execute all ready packages Q01–Q30. Do not stop after a routine design choice, test pass or subpackage and request another brief.
- Reuse completed work in the actual checkout. A listed obligation already implemented and evidenced needs an integration/compatibility check, not a duplicate framework.
- Make reversible implementation decisions within the contracts: helpers, data layouts, small versioned schemas, image layers, resource sizing, commands and test organization.
- Fix in-scope defects while preserving the invariant being tested. A repairable implementation failure is work, not an external blocker.
- When one prerequisite is genuinely unavailable, name it and continue independent packages. Zero live-generation authority does not block any required engineering package.
- Maintain one concise progress ledger, one acceptance matrix and one primary runbook. Use machine evidence for details; do not write a long new narrative after each intermediate run.
- Bound experiments and serialize heavy same-node workloads. More packages do not authorize unlimited CPU, disk, queue growth or test traffic.
- A session boundary means a resumable checkpoint for this programme. Record exact pending commands, source/image identities, protected/task resources and remaining tests. Do not promise asynchronous continuation or redefine included work as a future recommendation.
- Stop when every authorized feasible package is implemented and qualified, or remaining work has a concrete external prerequisite. Do not claim complete readiness if a required path failed or was replaced by an answer-bearing fixture.

### Design principle

Expand **integration and operational usefulness**, not the number of platforms. Do not create a second agent loop, arbitrary execution API, independent workflow engine, event bus, universal cache service, authorization system, deployment orchestrator or evidence database where the existing owner can implement the required bounded behavior.

## 4. Track A — interactive native execution

### Q01 — comparable measurements before optimization

Reuse existing telemetry, not a new monitoring platform. Establish a bounded baseline on fresh synthetic state with the Phase 3 profile. Freeze workload inputs, allowed commands, corpus/history sizes, numerical/runtime/model versions, resource settings, selected scopes, placement and controlled clocks before comparisons.

Measure separate intervals for queue wait, interpreter spawn, verification/overlay preparation, imports/readiness, context/history, model-fixture handling, native command dispatch, actual provider work, result capture and observation. Collect **provider-local** spans for the storage, E5 and Attention paths actually used; commitment spans are required only during chain testing. Missing active spans are missing data, not zero cost or an inferred server duration.

Record counts of interpreter starts, connections, requests, batch sizes, payload bytes, logical events, records charged and physical retained bytes. Trace metadata is diagnostic, not an authority for receipts or budgets. Omit raw private contents and avoid unbounded high-cardinality labels.

Derive a critical path only from observed parent/child relationships. Do not add nested times or sums of medians. Include errors, censored timeouts, overhead and cold/warm state. Retain the historical 19.93/28.69-second observations as historical rather than forcing a new environment to reproduce them exactly.

**Acceptance:** a rerunnable comparator; measured operation classes including recall, append, history, evidence/priority, workspace/context and two-agent handoff; documented instrumentation coverage and prioritized costs. No invented SLA or required percentage speedup.

### Q02 — reuse the actual native interpreter within one session

Extend the existing supervisor and source-checked launcher with an opt-in session-bound resident-worker profile. Keep the actual MeTTaClaw/PeTTa loop, parser, numerical functions and tool execution. A persistent Python supervisor that still launches a fresh native interpreter per input does not pass.

Prepare a worker before claiming an input; assign an existing durable occurrence; commit the normal result handoff; return to an explicit idle state; then accept another eligible input for the same frozen session. Prove at least five successive native inputs within one observed interpreter incarnation.

Audit native globals: previous input/results, pending commands, context/history views, pinned notes, imported state, credentials and bridge bindings. Mark each per-session, per-input or reconstructible. Journaled captures remain authoritative. Process IDs and mutable globals cannot become task identity or proof of completion.

Use finite resident-worker counts, idle lifetime and per-incarnation input/resource bounds. Do not recycle an active uncertain mutation to improve fairness. Do not move a warm worker between agents, private scopes or incompatible templates. Bind worker incarnation to assignments so a delayed old process cannot advance a replacement's state.

An idle crash may safely start another worker; a post-dispatch crash requires exact saved-result reconciliation or an uncertainty fence. No blind replay, deadline renewal or response regeneration.

**Acceptance:** real cold/warm native parity, saved-result recovery, bounded recycling and interleaved-session tests. If the pinned engine genuinely cannot support safe reuse, deliver validated startup amortization and the exact limitation; mark this gate PARTIAL rather than rename transport reuse as native reuse.

### Q03 — reuse verified immutable preparation

Content-address preparation using exact native source, overlay rules, runtime executable/libraries, immutable dependency selections and public configuration. Publish a prepared entry atomically only after verification. Do not include private session data or current credentials in a globally reusable cache.

Cache reuse requires actual read-only packaged inputs or another enforced immutability boundary. Do not claim cached hashes detect arbitrary modification of writable code. Check drift, unexpected files, symlink replacement, corrupt manifests and templates paired with different images. Preserve historical source validators under their old profiles.

Current authorization and credential rotation remain live checks, not preparation results. Model readiness is a separate lifecycle: warming the permitted native interpreter does not permit starting a generative backend.

Measure validation, overlay, import and first-input work before/after, plus resident memory. Avoid shipping developer-home files or unlisted prebuilt overlays.

**Acceptance:** repeated inputs reuse a verified prepared identity, deliberate source drift refuses, incomplete caches do not become ready, and a distribution-built worker starts without the original checkout.

### Q04 — bounded authenticated connection reuse and hydration

Inspect the actual exercised transports. Introduce connection/session reuse only where measured overhead and server support justify it. Key pools by endpoint identity, TLS trust/certificate selection and caller credential epoch; bound open/idle connections and request/response bytes.

Validate principal, scope, descriptor, profile, correlation and payload for every request/result. An authenticated connection is not a persistent authorization grant. Close or rotate pools on changed identity/trust selection; revocation must be enforced on already open connections.

Do not invisibly retry after possible transmission. A read retry retains its view, original deadline and attempt accounting. A mutation, model request, external send or chain submission requires the original operation's replay/observation rules. Partial body, stale connection, pod replacement and changed DNS are explicit cases.

Reuse declared `getMany` and batch observations. Preserve input order, per-item errors, lifecycle access and total bounds. Add a narrow versioned batch only when logical semantics already exist; do not introduce a general remote database query language.

**Acceptance:** real TLS connection reuse, lost/partial response handling, credential rotation and zero hidden mutation retry; fewer measured connections/round trips on equal workloads without larger disclosure or weakened checks.

### Q05 — incremental context and reference-based captures

Preserve the current native history-window and context rules; do not shrink the prompt, omit provenance or change ranking to obtain a faster comparison. Cache only immutable material with exact session/scope/head/view/profile/recipient bindings. Recheck current permission and withdrawal on release.

Materialize advancing history from the required changed window and batch chunk hydration. Captured old contexts remain exact; new inputs may select new heads. Cache deletion must reconstruct through owner ports, not evaluator files or legacy private databases.

Where measurement proves redundant full-payload copying, add an opt-in capture representation referencing an already committed retrievable immutable capture. Preserve every logical event, order, cause, original time, raw/transformed distinction and accepted result. Do not merge events because bytes match or invent independence because references differ.

Validate dependency lifetimes, scope, digest, total hydrated bytes, maximum depth and cycles. A reference to a volatile file or foreign SQLite row is insufficient. Commit the dependency before acknowledging the reference. Archives and backups must retain that dependency; missing data produces an explicit error, not a reconstructed guess.

**Acceptance:** actual native context equivalence; fewer measured duplicate reads/bytes; corrupt/missing/cyclic capture refusal; current-authority tests; reconstruction and fenced restore from exact references. No pruning, generative summarization or erased history.

## 5. Track B — portable service placement and developer interoperability

### Q06 — executable placement plans, not ad hoc endpoint edits

Build on current Helm values, provider descriptors and session selections. Define a small typed placement plan describing an **existing supported application composition**: required interface/profile, selected implementation, local-library or pod-HTTPS placement where permitted, scoped caller/service authority, resource/persistence prerequisites and dependency endpoints.

Validate the entire selected dependency graph before admitting business work. Detect missing providers, unsupported local/remote profiles, numerical/privacy incompatibilities, endpoint/certificate mismatch, ownership cycles and attempted foreign-volume mounts. Reject unsupported combinations rather than guessing a substitute.

Compile one plan into existing chart/configuration objects and caller selections. Show a dry-run diff and policy explanation. Do not create a scheduler or invent a universal deployment language. Do not put mutable occurrence state or credentials into the plan; reference separately managed Secrets.

Qualify a small useful matrix, not every combinatorial permutation: the historical local native profile; separated pod service execution; independently selected Embedding versus Search/storage; synthetic private cognition under its selected supported services. Changing placement must not change native business logic. Fresh sessions may choose a new plan; accepted work retains the old one.

**Acceptance:** actual selected configurations run, invalid graphs refuse early, the same native task works under at least two permitted placements, and generated diagrams reflect installed service edges. All execution remains on one node; this is logical placement flexibility, not multi-host evidence.

### Q07 — trusted provider admission, readiness and retirement

Extend the existing Registry/Resolver rather than replace it. Give operators supported add/inspect/disable/drain/retire operations for an allowlisted provider record. Separate advertised capability, successful compatibility selection, observed readiness, authority and any conformance evidence.

A provider cannot become trusted by self-announcing a name, returning a descriptor or passing a health probe. Admission requires operator policy and a pinned implementation/profile record. Unknown guarantees are not inferred from a version string.

Readiness may change selection for **new** work only. Accepted jobs, views, signed intents and captures stay bound to their selected provider. Disable blocks new assignment; draining does not discard retained results; retirement requires either accessible retained observations or an explicit unavailability contract. Never auto-fail over an uncertain mutation to another provider with no matching journal.

Expose bounded audit records and current-state observations. Metadata preflight must not leak private payloads merely to discover access rights. Use existing ConfigMaps/service state where adequate; no new discovery cluster.

**Acceptance:** new sessions select approved replacements; incompatible/unready endpoints are refused; old results remain observed through their original provider; withdrawal, revocation and compatible service restart do not reset state.

### Q08 — real contract-version and profile evolution

Turn the current compatibility examples into an executable matrix using actual clients and servers. Test old/old, compatible new/old, old/new when promised, and explicit refusal of unsupported required features or major/numerical/privacy guarantees.

Provide protocol fixtures for canonical encodings, error outcomes, bounded pages, immutable refs, request digests and occurrence semantics. Compatibility concerns behavior, not only JSON fields. Keep unknown mandatory fields rejected; adding an optional field does not authorize a weaker guarantee or silent default.

Use exact effective capabilities in native tool descriptions and admission. A rollout cannot change a previously accepted operation's selected schema, model, source view or time policy. Support old journals under their original identity; fresh opt-in profiles can be used for new semantics. No production migration is authorized.

Document who interprets version ranges and where exact profile selection is frozen. Do not duplicate negotiation logic in each provider or turn version discovery into arbitrary code loading.

**Acceptance:** wire calls complete for promised combinations; downgrade/privacy/numerical mismatch fails before effects; compatible rollout retains accepted work; incompatible rollback refuses. A resolver-only unit test cannot establish network interoperability.

### Q09 — an independently installable second-language client

Extend the existing contracts/client kit with a small second-language client for the actual stable HTTP interfaces. Prefer an already supported project toolchain; TypeScript is a reasonable default when available. If another installed toolchain is selected, record the reason and exact versions. Do not require new external SaaS.

The client must exercise metadata/profile selection, a scoped storage read, a bounded query or task submission, and saved-result/progress observation through real services. Keep native mathematical functions on their existing provider side; the client is not a second reasoning implementation.

Share normative schemas and golden wire cases, not a copy of Python business logic. Validate numeric strings, finite domains, identifiers, unknown states, error classes, order and deadlines consistently. Avoid lossy conversions of large integer values. Respect cancellation and retry classifications.

Build/install the package in a clean environment with the original Python agent and checkout unavailable. No host database, kubeconfig or provider key is supplied. CLI examples use scoped endpoint credentials from the normal secret mechanism.

**Acceptance:** real endpoint interoperability and malformed-response/authority tests from the second language, including disconnect and resumed observation. Record browser support only if exercised; a Node client is not automatically a browser client or another native Omega agent.

### Q10 — external-style provider and conformance kit

Reuse the independent provider work already delivered. Strengthen it into a small extracted package with a declared contract, selected persistence/recovery guarantees and a conformance entrypoint. Build outside the primary checkout and deploy it behind authenticated HTTPS.

At least one unchanged actual native consumer selects that provider in a fresh compatible session. It must not subclass the primary owner, open its tables or delegate state transitions back to it. Sharing canonical DTO validators and the pinned pure mathematical kernel is permissible where declared.

Provide a developer recipe from contract to server to conformance to deployment. Include incompatible-provider negative tests, profile/version selection, bounded retries, saved outcomes, scope errors and service credential rotation. Catalogue it truthfully as an independent reference/fixture provider when that is its class.

**Acceptance:** extracted build, installed client, actual provider and native consumer operate without a source-tree path dependency. This demonstrates implementation substitution, not hot migration of a populated journal or proof that a malicious provider obeys its contract.

## 6. Track C — portable remote work and bounded continuations

### Q11 — a closed, data-only execution envelope

Reuse DelegatedExecution, existing ToolDescriptor and task schemas. Define the smallest portable envelope for named existing operations: operation/profile/version; immutable input refs or bounded validated literals; initiating actor and explicit service delegation; selected provider identity; disclosure purpose; accepted deadline; per-stage and aggregate limits; stable task/correlation identity; and an authorized completion route.

No serialized interpreter heap, arbitrary source program, import path, shell fragment, callback URL or model-selected credentials is accepted. A continuation identifies a registered handler/workflow step and permitted input mapping—not arbitrary executable code.

Separate logical task identity from delivery identity and evidence/source identity. Replaying the same task through another transport key cannot mint another effect; an intentional new invocation has a new identity. Changed semantics under a bound task conflict.

Validate the actual operation's input and result contract, not only a common envelope. Keep the existing `inspect_atom` and named NAL operations as initial real executors; allow the typed native query boundary only through its correct owner semantics.

**Acceptance:** actual native caller emits the envelope, the selected worker executes, and the caller consumes its typed result. Unknown handler, wrong scope, stale descriptor, excessive limits, altered ref and unsupported guarantee fail before effects. No new native command is counted merely because its envelope changed.

### Q12 — durable asynchronous submission and completion

Make existing submit/observe/completion behavior usable as one documented SDK/native pattern. The caller persists intent before dispatch, receives a durable-acceptance or unknown outcome, can disconnect, and later observes the same logical operation and result.

Use existing execution journals, AtomStorage and Messaging. Completion references authoritative results; the caller hydrates/validates before accepting, then acknowledges delivery at the existing boundary. Do not create a mailbox for every synchronous read, or force all modules into an execution service.

Support bounded progress observation, caller restart, duplicate completion, lost submission reply, mailbox backpressure and late results. Polling/notification is not authority to reexecute. A failed status read cannot be interpreted as absence.

Persist delivery progress independently of worker result commit. An uncertain computation may repeat only under its own contract and remaining bounds; one logical admission/result is not an exactly-once physical-execution claim.

**Acceptance:** actual Omega delegates, disconnects/restarts and consumes the committed result through declared ports. Neither the controller nor test harness reads a worker journal to supply the answer. A real incomplete task remains pending/unknown rather than being repaired by a local calculation.

### Q13 — resumable bounded continuations for fixed workflows

Implement a narrow continuation facet in the existing application/task owner. It manages progress, not provider state. Register a small finite acyclic workflow composed only of allowlisted tools and immutable result mappings. Bound nodes, edges, depth, inflight steps, total requests and output bytes before admission.

Persist the accepted workflow definition, exact step inputs, selected providers, step identities, prerequisite results and next permitted transition. A step becomes ready only when its required typed outputs and owner receipts exist. Prior to an effect, recheck current authority and the remaining aggregate limits.

Begin with two useful workflows: (a) storage/reference -> named remote inspection -> correlated native consumption; (b) actual native retrieval/task result -> approved inspection artifact -> separately approved fixed isolated-chain commitment. Reuse the original chain operation and explicit artifact consent; a workflow approval does not authorize arbitrary deployment. A trusted approved-artifact policy may bind the exact generated result only after authorized retrieval and validation; accepting the workflow alone must not preapprove an unknown future digest.

A recorded model may request a registered workflow but cannot rewrite its graph or choose a new callback. No recursion, arbitrary fan-out, general planner, dynamically generated code or speculative parallel effects.

After interruption, derive progress from committed captures/receipts. Do not serialize native process memory or rerun completed steps to reconstruct it. A failed prerequisite blocks dependent steps; unrelated diagnostic reads may continue. No automatic rollback of external effects.

**Acceptance:** stop the caller at multiple boundaries, resume the same graph without repeating committed effects, preserve partial/unknown outcomes and prove the chain artifact came from that workflow. Call this a **bounded application continuation**, not arbitrary process migration or distributed exactly-once execution.

### Q14 — cancellation, deadlines and hierarchical budgets

Unify only the necessary task-level view over existing owner limits. An overall workflow/task budget may allocate child allowances, but cannot replace owner-enforced per-operation limits or create a cross-owner transaction.

Reserve children durably before dispatch. Child deadlines cannot outlive the accepted parent authorization window unless a separately specified observation-only phase allows reading old outcomes. Lost allocations remain spent or reconciled from authority; they are not free credit because an acknowledgment was lost.

Cancellation before dispatch terminalizes safely. Cancellation during work prevents future permissible stages where enforceable but does not retract an emitted message, undo an atom or replace an already signed chain intent. Return explicit accepted, completed, cancel-requested, expired-before-start or needs-reconciliation observations as supported.

Exercise late results, cancellation-versus-dispatch, two-agent wrong-recipient responses and credential revocation. Preserve provenance: agent B repeating agent A's source is not independent corroboration.

**Acceptance:** fixed bounds survive caller/provider restart, graph resumption and session closure. Safe independent work progresses while dependent uncertain mutations stay fenced. No general scheduler, global budget-bank transaction or arbitrary retry loop is introduced.

### Q15 — owner commit notifications with replayable catch-up

## 11. Cross-cutting invariants

1. **One state owner.** No consumer mounts another owner's mutable journal, reads foreign SQL or writes implementation-specific private fields.
2. **Native execution stays native.** No Python imitation, precomputed result table or changed mathematical profile substitutes for the selected native operation.
3. **Current authority.** Every effect and protected result/context release checks current actor, scope, recipient and selected policy, including cache and replay paths.
4. **Identity is semantic and occurrence-bound.** Text equality, timestamp or a hash alone is neither task identity nor permission; source/evidence identity differs from command and delivery identity.
5. **Original bounds survive.** Deadlines, spent reservations, unknown effects and selected views persist through reconnection, worker reuse, rollout, archival and restore.
6. **No hidden fallback.** Unavailable remote providers do not become local success, another model, an empty memory result or a recorded-provider replacement.
7. **No silent resend.** Unknown external sends and uncertain signed chain operations follow their original observation/replay protocol, not a new timestamp or operation key.
8. **Captures are exact but not permanent permission.** Saved bytes stay unchanged; withdrawal/revocation may deny their later disclosure without rewriting history.
9. **No fabricated provenance.** A prior is not an observation; copying an event or receiving an agent report does not create independent evidence.
10. **Separate stages.** Acceptance, execution, storage, publication, readiness, capture, admission, socket outcome, peer receipt and chain finality remain individually observable.
11. **Rebuild derived state only.** An index/cache/presentation is reconstructible; missing authoritative data cannot be repaired by guessing or rerunning side effects.
12. **No global atomicity claim.** Owner snapshots, continuation steps, budget allocations and backup cuts commit independently; report partial outcomes honestly.
13. **Retention is finite.** Archive tiering is not deletion, infinite capacity, independent backup or stronger authority. Spent receipts remain authoritative.
14. **Security evidence is bounded.** Namespace separation, TLS and local hashes do not prove malicious-host safety or production tenancy isolation.
15. **Historical records remain historical.** New tests cannot reconstruct missing prior payloads or turn unknown usage into zero.
16. **Models remain fixtures here.** Every generation response is labelled recorded; actual native dataflow and deterministic/chain effects are real only where executed.
